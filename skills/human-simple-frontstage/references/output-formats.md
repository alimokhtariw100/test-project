# قالب‌های خروجی

قالب را براساس درخواست کاربر انتخاب کن. توضیح اضافه نده وقتی کاربر خروجی مستقیم می‌خواهد.

## 1. فقط متن نهایی

برای درخواست‌هایی مثل «فقط متن»، «فقط اسم‌ها» یا «مقدمه نده»:

```text
[فقط نسخه نهایی]
```

هیچ عنوان، تحلیل یا گزینه اضافی نیاور.

## 2. جایگزینی دقیق

برای تغییر Copy موجود در سایت یا اپ:

```text
متن فعلی:
«[متن موجود]»

جایگزین دقیق:
«[متن نهایی]»
```

اگر نکته اجرایی لازم است، فقط بعد از متن اضافه کن:

```text
نکته اجرا:
[فقط چیزی که برای توسعه‌دهنده لازم است]
```

## 3. جدول Bulk UI

| جایگاه / کلید | متن فعلی | متن نهایی | نکته اجرا |
|---|---|---|---|
| Hero headline | ... | ... | حداکثر 3 خط روی موبایل |

ستون نکته اجرا را فقط وقتی نگه دار که واقعاً لازم است.

## 4. Audit کوتاه

### [نام بخش]

**مشکل:** [مشکل مشخص]

**اثر روی مخاطب:** [چرا فهم، اعتماد یا اقدام را خراب می‌کند]

**جایگزین دقیق:**
«[متن پیشنهادی]»

## 5. سه نسخه معنادار

فقط وقتی کاربر گزینه می‌خواهد:

**نسخه 1 — مستقیم**
«...»

**نسخه 2 — گرم‌تر**
«...»

**نسخه 3 — کوتاه‌تر**
«...»

نسخه‌ها باید تفاوت استراتژیک داشته باشند، نه تغییر چند واژه.

## 6. فرم و Flow

```text
مرحله 1
عنوان: «...»
توضیح: «...»
فیلد: «...»
راهنما: «...»
دکمه: «...»

مرحله 2
...

خطاها
- [شرط]: «[پیام]»

موفقیت
«[تأیید اتفاق + قدم بعدی]»
```

## 7. Hero کامل

```text
برچسب کوچک:
«...»

تیتر اصلی:
«...»

خط تأکیدی:
«...»

توضیح:
«...»

دکمه اصلی:
«...»

دکمه دوم:
«...»
```

هر جزء فقط وقتی وجود داشته باشد که تجربه واقعاً به آن نیاز دارد.

## 8. پیام خطا

```text
شرایط بروز:
[چه زمانی دیده می‌شود]

متن:
«[چه شد + حالا چه کار کند]»
```

مثال:

```text
شرایط بروز:
شماره موبایل کوتاه یا ناقص است.

متن:
«شماره‌ت کامل نیست. یه بار چکش کن.»
```

## 9. پیام موفقیت

```text
«[چه چیزی انجام شد]. [قدم بعدی یا انتظار واقعی].»
```

مثال:

«درخواستت ثبت شد. بعد از بررسی باهات تماس می‌گیریم.»

## 10. متن پیاده‌سازی‌شده در کد

وقتی Copy داخل Repo تغییر می‌کند، گزارش را کوتاه نگه دار:

```text
UPDATED COPY:
- [file:line or component] — [summary]

UNCHANGED:
- routes
- IDs
- form keys
- backend contract

VERIFIED:
- mobile readability
- CTA destination
- RTL
- no unsupported promises
```

## قانون خروجی

- درخواست کاربر بر قالب‌های بالا مقدم است.
- اگر کاربر یک قالب دقیق داده، همان را عیناً دنبال کن.
- اگر فقط یک متن می‌خواهد، Audit را به او تحمیل نکن.
- اگر تصمیم باز و واقعی وجود ندارد، گزینه‌های اضافی نساز.
