# Persian Style Guide

Use this guide for natural, readable Persian frontstage copy.

## 1. Choose one register per surface

Do not mix formal and conversational Persian accidentally.

### Human-neutral

Suitable for most product UI:

- «درخواستت ثبت شد.»
- «شماره‌ت رو یه بار چک کن.»
- «آموزش رو ببین.»

### Warm-personal

Suitable for founder-led education and community:

- «بگو دقیقاً چی می‌خوای بسازی.»
- «از همین‌جا شروع کن.»

### Trust-formal

Suitable for payment, contracts, privacy, legal, medical, and high-stakes contexts:

- «درخواست شما ثبت شد.»
- «لطفاً شماره تماس را بررسی کنید.»

Use the project’s established voice. Do not switch from «تو» to «شما» inside one flow unless the audience or legal context changes intentionally.

## 2. Spoken does not mean careless

Natural Persian may use:

- «رو» instead of «را»
- «می‌خوای» instead of «می‌خواهی»
- «برات» instead of «برای تو»

Use them only when they fit the selected voice. Keep spelling, punctuation, and meaning precise.

Avoid writing every spoken contraction phonetically. The goal is natural reading, not transcription of every sound.

## 3. Use نیم‌فاصله consistently

Prefer:

- می‌خوای
- می‌تونی
- می‌شه
- به‌درد
- مرحله‌به‌مرحله
- دست‌به‌کار
- هوش مصنوعی‌ات, only if grammatically needed and visually readable

Do not overcorrect product names, URLs, code, file paths, or identifiers.

## 4. Use Persian punctuation naturally

- Use Persian comma: `،`
- Use Persian question mark: `؟`
- Put punctuation outside closing Persian quotation marks when grammatically appropriate.
- Avoid repeated punctuation such as `!!!` and `؟؟؟` unless the user explicitly requests social-native emphasis.
- Use the Persian ellipsis sparingly; do not use it to hide incomplete thinking.

## 5. Preserve exact technical strings

Do not alter:

- URLs
- file paths
- event names
- code identifiers
- API field names
- product and tool names
- version numbers

Examples:

- `Google Flow`
- `ChatGPT`
- `/api/leads`
- `diagnostic_complete`
- `1920 × 1080`

Explain the term around the exact string when needed instead of renaming it.

## 6. Persian and Latin digits

Use Persian digits in ordinary Persian-facing copy when the project does so consistently:

- ۳ سؤال
- ۳۰ دقیقه
- ۴٬۹۰۰٬۰۰۰ تومان

Keep Latin digits where they are part of:

- code
- URLs
- version numbers
- technical dimensions when the design system requires it
- globally recognized product names such as `GPT-5`

Do not mix digit styles inside one number.

## 7. Mixed Persian and English

- Keep the English product name intact.
- Add a short Persian explanation only when the audience may not know it.
- Avoid parentheses around every English word.
- Avoid writing an English term, a transliteration, and a formal Persian translation all at once.

Bad:

«وارد بخش Workflow (ورک‌فلو / گردش کار) شوید.»

Better:

«مراحل کار رو باز کن.»

Or for an AI-aware audience:

«Workflow رو باز کن؛ همون بخشی که مراحل کار اونجاست.»

## 8. Write active sentences

Prefer:

«درخواستت رو بررسی می‌کنیم.»

Avoid:

«درخواست شما مورد بررسی قرار خواهد گرفت.»

Prefer:

«شماره‌ت رو وارد کن.»

Avoid:

«شماره تماس می‌بایست وارد گردد.»

## 9. Remove administrative filler

Avoid as defaults:

- می‌باشد
- می‌گردد
- لذا
- بدین وسیله
- خواهشمند است
- کاربر گرامی
- به اطلاع می‌رساند
- در راستای
- فرایند مربوطه
- نسبت به انجام

Use direct language unless the legal document requires formal wording.

## 10. Control abstraction

Words such as these often need a concrete explanation:

- تحول
- رشد
- موفقیت
- مسیر
- تجربه
- ارزش
- سیستم
- حرفه‌ای
- هوشمند
- اختصاصی

Ask what changes in reality.

Weak:

«یک تجربه هوشمند و اختصاصی برای رشد شما»

Better:

«چند سؤال جواب بده تا فقط آموزش‌های مرتبط با کارت رو ببینی.»

## 11. Avoid buzzword repetition

A useful brand word becomes empty when repeated in every heading, button, and card.

Example:

Do not write:

- مسیر رایگان
- مسیر مناسب
- تست مسیر
- مسیر اصلی
- مسیر فارسی
- مسیر یادگیری

Use natural alternatives:

- شروع کن
- آموزش رو ببین
- قدم بعدی
- انتخاب مناسب
- کمک اختصاصی

## 12. Respect the audience

Do not write as if the audience is unintelligent.

Avoid:

- exaggerated baby talk
- forced slang
- humiliating examples
- unnecessary mockery
- fake intimacy

Use familiar language while preserving adult dignity and professional authority.

## 13. Use emoji only with intent

Default for websites and product UI: no emoji.

Allow limited emoji when the user explicitly requests a social, playful, or conversational tone.

Never use emoji as the only carrier of meaning, status, warning, or action.

## 14. Mobile line-breaking

For mobile headlines:

- keep one main thought
- avoid line breaks that separate a verb from its object
- keep tool names and numbers intact
- prevent a single weak word from sitting alone on the last line
- place the most important phrase in the first visible lines

Do not insert manual `<br>` or hard line breaks unless the target width is known and tested.

## 15. Read-aloud check

Before approval, read the final Persian aloud at normal speed.

Rewrite when:

- the breath pattern is unnatural
- the sentence needs rereading
- the pronoun reference is unclear
- the word order sounds translated
- the speaker would never say it that way

The final copy should sound intentional, not merely grammatical.
