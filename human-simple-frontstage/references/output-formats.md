# الگوهای خروجی

فرمت خروجی را از درخواست کاربر انتخاب کن. اگر کاربر فرمت را مشخص کرده، همان فرمت از همه الگوهای این فایل مهم‌تر است.

---

## 1. فقط متن نهایی

برای درخواست‌هایی مثل:

- «فقط متن بده»
- «لیست اسم فقط»
- «بدون توضیح»
- «همینو آماده کپی بده»

فقط خروجی نهایی را بده.

```text
قرار نیست همه‌ی هوش مصنوعی رو یاد بگیری.
فقط چیزی که به درد تو می‌خوره.
```

مقدمه، تحلیل، امتیاز و جمع‌بندی اضافه نکن.

---

## 2. جایگزینی دقیق

برای تغییر متن موجود در سایت یا اپ:

```text
متن فعلی:
«هوش مصنوعی را فقط یاد نگیر؛ یاد بگیر که استفاده‌اش کنی.»

جایگزین دقیق:
«قرار نیست همه‌ی هوش مصنوعی رو یاد بگیری؛ فقط چیزی که به درد تو می‌خوره.»
```

اگر Implementation note لازم است:

```text
نکته اجرا:
این متن در موبایل به دو خط اصلی و یک خط تأکیدی تقسیم شود.
```

نکته اجرا را فقط وقتی بده که از اشتباه واقعی جلوگیری می‌کند.

---

## 3. Copy Deck چندبخشی

برای صفحه کامل:

```markdown
## HERO

**Eyebrow**
هوش مصنوعی، به زبان آدمیزاد.

**Heading**
قرار نیست همه‌ی هوش مصنوعی رو یاد بگیری.

**Emphasis**
فقط چیزی که به درد تو می‌خوره.

**Body**
کمکت می‌کنم از بین این همه ابزار و آموزش، بفهمی چی به دردت می‌خوره و باهاش چیزی واقعی بسازی.

**Primary CTA**
رایگان شروع کن

**Secondary CTA**
آموزش‌ها رو ببین
```

Copy Deck باید قابل انتقال مستقیم به Design یا Code باشد.

---

## 4. جدول Bulk UI

برای تعداد زیاد String:

| Key / Surface | متن فعلی | متن نهایی | نکته اجرا |
|---|---|---|---|
| `hero.title` | هوش مصنوعی را فقط یاد نگیر... | قرار نیست همه‌ی هوش مصنوعی رو یاد بگیری. | Heading اصلی |
| `hero.primary_cta` | شروع مسیر رایگان دبی | رایگان شروع کن | Route فعلی حفظ شود |
| `form.phone_error` | شماره نامعتبر است | شماره‌ت کامل نیست. یه بار چکش کن. | نزدیک Field |

Key فنی را فقط وقتی کاربر یا Repo دارد استفاده کن. از خودت Key ساختگی نساز مگر Task شامل طراحی Content model باشد.

## 5. Audit فشرده

```markdown
### 1. Hero headline

**مشکل**
Generic است و تفاوت برند را نشان نمی‌دهد.

**اثر روی مخاطب**
مخاطب می‌فهمد موضوع AI است، اما نمی‌فهمد چرا این برند متفاوت است.

**جایگزین دقیق**
«قرار نیست همه‌ی هوش مصنوعی رو یاد بگیری؛ فقط چیزی که به درد تو می‌خوره.»
```

Audit را با فهرست بلند نظریه‌ها شلوغ نکن. هر Finding باید جایگزین قابل اجرا داشته باشد.

## 7. Variantهای معنادار

وقتی کاربر چند گزینه می‌خواهد، هر گزینه باید Strategy متفاوتی داشته باشد:

```markdown
### مستقیم
«رایگان شروع کن.»

### نتیجه‌محور
«اولین خروجی‌ت رو بساز.»

### راهنمایی‌محور
«ببین از کجا شروع کنی.»
```

پنج نسخه با جابه‌جایی دو واژه تولید نکن.

اگر یک گزینه آشکارا بهتر است، آن را مشخص کن؛ مگر کاربر فقط لیست خواسته باشد.

---

## 8. فرم کامل

```markdown
## مرحله 1

**عنوان**
چطور باهات تماس بگیریم؟

**فیلد نام**
نام و نام خانوادگی

**فیلد شماره**
شماره موبایل

**خطای شماره**
شماره‌ت کامل نیست. یه بار چکش کن.

**دکمه**
مرحله بعد

## پیام موفقیت

درخواستت ثبت شد. بعد از بررسی باهات تماس می‌گیریم.
```

هر سؤال باید یک تصمیم روشن داشته باشد.

## 9. Error / Success Matrix

| حالت | متن |
|---|---|
| نام خالی | اسمت رو بنویس. |
| شماره ناقص | شماره‌ت کامل نیست. یه بار چکش کن. |
| خطای شبکه | درخواستت ارسال نشد. اینترنتت رو چک کن و دوباره بزن. |
| ارسال تکراری | درخواستت قبلاً ثبت شده. |
| موفقیت | درخواستت ثبت شد. بعد از بررسی باهات تماس می‌گیریم. |

متن خطا باید با رفتار واقعی سیستم هماهنگ باشد. مثلاً «قبلاً ثبت شده» فقط وقتی استفاده شود که Backend واقعاً Duplicate را تشخیص می‌دهد.

## 10. متن حساس با خلاصه و جزئیات

برای Privacy، Consent، Payment یا موضوعات پرریسک:

```markdown
**خلاصه ساده**
برای بهترکردن سایت، با اجازه تو آمار کلی استفاده رو بررسی می‌کنیم.

**جزئیات کامل**
[متن کامل و دقیق که شرایط، ابزارها، داده‌ها و حق انتخاب را حفظ می‌کند.]
```

خلاصه ساده جای متن کامل قانونی را نمی‌گیرد، مگر الزامات پروژه صریحاً چیز دیگری بگویند.

## 11. متن آموزشی لایه‌ای

```markdown
**یک‌خطی**
پرامپت یعنی متنی که به هوش مصنوعی می‌دی.

**مثال**
مثلاً به‌جای «یه عکس بساز»، می‌گی سوژه کجاست، نور چطوره و چه حسی می‌خوای.

**کاری که الان انجام بده**
موضوع عکست رو در یک جمله بنویس و سه جزئیات بهش اضافه کن.
```

لایه اول باید به‌تنهایی قابل فهم باشد.

## 12. Social / Story sequence

```markdown
### استوری 1
«الان بیشتر تو کدومش گیری؟»

[ساخت عکس] [ساخت ویدیو]

### استوری 2
«مشکل بیشتر آدما کمبود ابزار نیست؛ نمی‌دونن کدوم ابزار به دردشون می‌خوره.»

### استوری 3
«فردا یکی‌شون رو صفر تا صد می‌سازیم.»
```

هر Story یک کار اصلی داشته باشد. متن را مثل Paragraph سایت روی استوری نریز.

## 13. Repository-ready replacement list

```markdown
# COPY REPLACEMENTS

## `public_html/index.html`

### Hero badge

Current:
`آموزش و اجرای هوش مصنوعی، برای کار واقعی`

Replace with:
`هوش مصنوعی، به زبان آدمیزاد.`

Constraints:
- Preserve element ID and classes.
- Do not change route or event handler.
```

این فرمت برای Codex/Claude Code مناسب است چون مرز Copy و Code را روشن می‌کند.

## 14. Blocked output

اگر متن خوب به Feature یا Fact تأییدنشده وابسته است:

```markdown
**BLOCKED**

این جمله وعده می‌دهد که نتیجه شخصی‌سازی‌شده فوراً ساخته می‌شود، اما منبع فعلی فعال‌بودن این Feature را تأیید نمی‌کند.

برای نهایی‌کردن متن باید مشخص شود:
- Feature واقعاً فعال است یا نه.
- نتیجه چه زمانی نمایش داده می‌شود.
```

نسخه خوشگل ولی غیرواقعی تولید نکن.

---

## 15. قالب انتخاب نهایی

وقتی چند گزینه داده‌ای و کاربر تصمیم می‌خواهد:

```markdown
**پیشنهاد نهایی من:**
«...»

**دلیل:**
[یک یا دو جمله مشخص، نه مقاله.]
```

اگر کاربر گفته «فقط لیست»، دلیل را حذف کن.

---

## قانون پایانی

فرمت خروجی باید کار بعدی را آسان کند:

- مخاطب نهایی → متن تمیز
- Founder → تصمیم روشن
- Designer → Copy Deck
- Developer → Replacement list یا Table
- Auditor → Finding + impact + exact replacement

خروجی نباید فقط خواندنی باشد؛ باید قابل استفاده باشد.
